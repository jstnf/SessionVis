# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SessionVis is a native macOS app (Swift package, macOS 15, Swift 6 strict concurrency) that tails Claude Code transcripts under `~/.claude/projects/` for one directory per tab and draws each as a gource-style radial file graph: each session is an orb that fires beams at the files it reads and edits, subagents sit inside their parent's halo, and a floating list mirrors iTerm's session-status panel. The README covers run commands, gestures, privacy and known gaps.

## Commands

```sh
swift build                                   # debug build, must stay at 0 warnings
swift test                                    # whole suite (Swift Testing)
swift test --filter SessionStoreTests         # one suite
swift test --filter SessionStoreTests/subagentEndsOnParentResultOrOwnTurnEndAndIsRemovedAfterLinger   # one test
swift run SessionVis --dir /path/to/repo                                        # live against a repo
swift run SessionVis                                                            # reopen the persisted tabs
swift run SessionVis --replay <transcript.jsonl> --speed 20 --dir <repo>        # replay one transcript
scripts/bundle-app.sh && open dist/SessionVis.app --args --dir <repo>           # release .app bundle
scripts/make-icon.sh                          # regenerate Assets/AppIcon.icns via the IconGen target
```

The directory must be given with `--dir` (it selects or adds that tab; no arguments restores the tabs persisted under the `tabs` default). A bare path argument makes AppKit treat it as a document to open and no window appears.

## Architecture

Three targets. `SessionVisCore` is pure Foundation/CoreGraphics (plus CoreServices for FSEvents) and holds everything testable; `SessionVis` is the SwiftUI/AppKit shell; `IconGen` draws the Dock icon with CoreGraphics. All tunables (durations, radii, limits) live in `SessionVisCore/Constants.swift`; do not scatter new magic numbers.

Data flows one way:

1. **Discovery** (`Discovery/`): `SessionDiscovery` finds `<uuid>.jsonl` transcripts and `<uuid>/subagents/agent-<id>.jsonl` + `.meta.json` under the project folder. `WorktreeLister` asks `git worktree list --porcelain` for every checkout of the repository (falling back to the directories under `.claude/worktrees` when git cannot be run) and `PathFolder`, built from that registry, folds any path inside any checkout back onto the main tree, tagged with the worktree's name; `rootPath(of:)` answers where an origin's files live. Every holder of a folder (store, live source, watcher, simulation) has `setFolder(_:)`, and the app swaps it when a vnode watcher on `<git common dir>/worktrees` fires. A transcript belongs to the directory based on its first `cwd` record; membership is tri-state (unknown until a cwd is seen) so just-created transcripts are not rejected forever.
2. **Transcript layer** (`Transcript/`): `TranscriptTailer` reads new bytes; `TranscriptParser` turns each JSONL record into `TranscriptEvent`s (user prompt, tool use/result, assistant text, turn ended, interrupted, title, relocated, worktree, task notification, usage, compacted). Assistant records are split per content block with `stop_reason` only on the last one.
3. **Sources** (`Live/LiveSource.swift`, `Replay/ReplaySource.swift`) emit `SourceEvent`s (session/subagent appeared, line, hook, diagnostics, initial load complete, and `diskChanges`, which the app sends from the watcher's deltas rather than a source). Replay rebases timestamps to the store clock.
4. **Store** (`Model/SessionStore.swift`, an actor) applies events to `AgentRecord`s, each with a `StatusMachine` (idle/working/waiting/ended with timestamp precedence: a status applies only if its timestamp is >= `statusAt`, which starts at `.distantPast` so history drives status at launch). It records file `Touch`es (which carry the toucher's hue and title). A subagent takes a `shade` of its session's hue from an `ordinal` the source supplies (the 1-based rank of its transcript by creation date among every `agent-*.jsonl` of the session, idle ones and ones whose metadata is not written yet included; live and replay use the same discovery ranking, and the live source re-sends a tracked subagent's ordinal as `subagentOrdinal` when a rescan changes it), cycling through `Constants.subagentShades` and bumped once when it would equal its immediate subagent parent's shade (`HuePalette.shade(forOrdinal:avoiding:)`); the shade is recomputed when the parent changes, so it depends only on the final tree. It can shift live when the folder changes (a late metadata file, a deleted transcript) and always matches a relaunch. Touches and snapshots carry it. It also records Bash calls as `CommandEvent`s classified by `CommandClassifier` (a chain with several git milestones becomes one event per milestone, in order), filling commit hashes from the matching tool result. Bash commands also go through `ShellTouchParser`, a fixed verb grammar whose operands and redirections become touches; a shell or search read is kept only if its target exists on disk. The watcher's disk changes arrive as `diskChanges` events that the store credits, after a settling delay and once the initial load is in, to the one agent with a running command. From `usage` events it keeps per-agent input and output totals deduplicated by message id (a response split across records repeats the id; the last repeat wins), the latest context size under timestamp precedence (a `compacted` event resets it), the model id and a window from `Constants.contextWindows`, bumped to the next tier when an observation exceeds it; the snapshot publishes them quantised. It publishes `StoreSnapshot`s, throttled to `snapshotInterval`.
5. **Simulation** (`Sim/Simulation.swift`, a `Sendable` value type) consumes snapshots and `TreeDelta`s: avatars with eased positions, beams, heat (3 s glow), lingering tint on touched files and on every edge from the root down to them (both fade over `tintDuration`; a shared edge takes the newest toucher's hue and shade), particles, halos (convex hull of a main orb and its subagents), dying/born node animations, ghost files (origin set without main) drawn as rings that land when main gains them, command pulses, commit ripples and badges, a camera that auto-fits until the user pans or zooms, or follows one agent (`followTarget(for:)` frames the agent's main, its halo and recent touches at a zoom clamped to `followMinZoom…followMaxZoom`; centre and zoom ease at separate rates; `stopFollowing` holds the camera). A `FileFilter` of gitignore-like `GlobPattern`s (`Filter/`) is applied here, not upstream: files it hides are kept out of the tree with their origins in `hidden`, `setFilter` moves them in and out without a rescan, watcher deltas are split into a hidden side and a visible remainder, and a file touch on a hidden path is consumed (sequence advanced, nothing drawn, no pull on the orb). Focus mode (`Simulation+Focus.swift`) keeps `lastTouchAt` per file, judges a file active when touched within `focusActiveWindow` or still tinted, re-judges every `focusRelayoutInterval` of simulation time and relayouts only when the set changed; the renderer draws inactive files and their edges faint while it is on, and nothing is ever removed. Hit testing uses layout positions; drawing uses eased `renderPositions`.
6. **Tree** (`Tree/`): `FileTreeScanner` seeds the whole repo (git-tracked files when possible, capped at `maxTreeFiles` distinct paths across checkouts) once for the main checkout and once per registered worktree (main's listing skips checkouts nested inside the root), tagging each file with its origins; `RadialLayout` places it (with an optional active set, `LayoutWeights` widen active directories' sectors and pack idle files on their rings); `RepoWatcher` (FSEvents, one stream over the root plus every worktree root outside it, recreated when the registry changes) emits one `TreeDelta` per origin that changed (added/removed/moved by unique-name pairing, with a full snapshot attached so the simulation can reconcile files it inserted from touches; deltas also carry `changed` paths (rewritten files, mapped from FSEvents' real paths back onto the watched directory) and a timestamp).
7. **App** (`Sources/SessionVis/`): `Workspace` (main actor, `@Observable`) owns the ordered `TabList` (Core; tabs are unique by `PathFolder.canonical` path; persisted as one JSON blob under the `tabs` default, replay tabs excluded), one `RepoSession` per tab, the app-wide `HookRouter` and the hook marker, and routes the launch arguments through `TabList.launchAction(for:)`. `RepoSession` is the per-directory model: it owns the source, store and a `SimulationBox` (which also holds the renderer's `DirectoryListCache`), plus the watcher, registry watcher, filter, selection and hover; only the selected tab is in the view hierarchy, so only it is stepped and drawn, a hidden tab polls its store at `hiddenSnapshotInterval` (aging and retirement run in the poll) and keeps its watcher, and on reveal the box runs `Simulation.catchUp` so effects that piled up unstepped expire instead of bursting; a session registers with the router at the start of its open so early payloads are delivered, and a session never outlives its tab; the window is a single `Window` and ⌘W is Close Tab only while the main window is key (a focused scene value), otherwise the system File > Close; a `TabStripView` sits above the scene in a `VStack`; `SceneView` steps the simulation inside `TimelineView(.animation)` and `SceneRenderer` draws into a `Canvas`; `InputCaptureView` is an NSView forwarding scroll/pinch/hover/click and, as first responder, `keyDown` translated into a `KeyCommand` (`Input/KeyCommand.swift` maps key code and modifiers; a new shortcut is a new case and one mapping line, never a view change); `OverlayListView` is the floating session list; `TooltipView` follows the hover point. `FileFilterStore` keeps the hidden-file rules per directory in UserDefaults and `HiddenFilesSection` is their Settings UI. `RepoSession+Terminal.swift` brings a session's terminal tab to the front through the core `Terminal/` folder: `TerminalLocator` is pure parsing of Claude Code's `~/.claude/sessions/<pid>.json`, `ps` output and AppleScript results, and `TerminalOpener` validates the pid with `ps` (alive, on a tty, started when the file says) and sends one find-and-select AppleScript per running terminal app, iTerm2 before Terminal; the app only decides which apps are running.

Optional hooks: a shell snippet (shown in Settings, `Hooks/HookSnippet.swift`) writes Claude Code hook payloads into `~/Library/Application Support/SessionVis/hooks/`, but only while the app's marker file exists. One `HookRouter` for the whole app drains the spool through a single `HookSpoolReader` (the reader deletes a payload as it reads it, so two readers would steal from each other) and delivers each payload as a `.hook` event to every tab whose `PathFolder` accepts its `cwd`, for exact "waiting on permission" states. The app works without hooks.

## Agent lifecycle rules worth knowing before touching the store

These span `SessionStore`, `StatusMachine` and the parser, and were each learned from real transcripts:

- Ended agents are **retired**, never deleted. Resumed subagents keep writing to the same transcript, and a later line un-retires the record with its original title, hue and parent, reviving the parent chain too.
- A subagent ends on its parent's `tool_result` for the spawning `Agent` call, on its own `end_turn` with no pending tools, on a `SubagentHandback` tool call, on a `[Request interrupted by user]` record, on the parent's `<task-notification>` (a user record or a `queue-operation` enqueue record), or on a `SubagentStop` hook.
- Ends the agent caused itself (hand-back, turn end, interruption, task notification) are **sticky**: only a new user prompt in its transcript or a `UserPromptSubmit` hook revives it. Ends caused by the parent stay revivable, because for background subagents the parent's `tool_result` arrives at launch ("Async agent launched") and the child's next line must bring it back.
- Lines older than an end never revive a record but still count for touches and parentage, since at launch a parent's whole file is read before its subagents' files.
- Main sessions age to `ended` after `activeWindow` without activity; subagents are never aged, they end only through the rules above.

## Verifying visually

Unit tests cover the core; the rendering can only be checked by launching the app. Launch the built binary detached (outside any sandbox), find its window with the CGWindow list, and capture it with `screencapture -x -o -l<windowID>`. Subagents cannot see the display, so the controlling session does this itself. When adding temporary diagnostics to a detached launch, write to stderr: stdout is block-buffered and lost if the process is killed.

The window is a full-size content view. The `Canvas`, `InputCaptureView` and `TooltipView` must all stay inside the safe-area frame (no `.ignoresSafeArea()` on them, only on the background colour), or hover coordinates drift by the title-bar height.
